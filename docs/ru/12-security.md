# Безопасность / Security

## Уровень 1. Простыми словами

GreenCore не доверяет клиенту.
Сервер проверяет каждое сообщение от клиента.

## Уровень 2. Техническое объяснение

Архитектура строится вокруг правила:

```text
Клиент просит → Сервер проверяет → Сервер решает → Клиент выполняет → Сервер подтверждает
```

## Обязательные правила

1. Никогда не доверять клиенту.
2. Не принимать `source` из payload.
3. Использовать серверный `source` события.
4. Не принимать координаты спавна от клиента.
5. Не принимать модель от клиента.
6. Не принимать состояние игрока от клиента.
7. Не принимать Session ID от клиента.
8. Не принимать Decision ID, не созданный сервером.
9. Проверять тип каждого значения.
10. Проверять длину каждой строки.
11. Ограничивать частоту событий.
12. Проверять жизненный цикл.
13. Проверять срок действия решений.
14. Не обрабатывать одно решение дважды.
15. Маскировать идентификаторы.
16. Не выполнять код из строк.
17. Не использовать небезопасные глобальные таблицы.
18. Не разрешать клиенту напрямую менять серверную сессию.
19. Не создавать автоматическую систему банов.
20. Не скрывать критические ошибки.

## Валидация payload

Все данные от клиента считаются недоверенными.

```lua
function GCValidation.ClientReady(payload)
    if type(payload) ~= 'table' then
        return false, 'GC-PAYLOAD-TYPE-001'
    end

    if type(payload.clientVersion) ~= 'string' then
        return false, 'GC-PAYLOAD-VERSION-001'
    end

    if #payload.clientVersion > 32 then
        return false, 'GC-PAYLOAD-VERSION-002'
    end

    return true
end
```

## Rate limit

Каждое событие имеет ограничение частоты.

```lua
GCConfig.Security.rateLimits = {
    clientReady = {
        intervalMs = 3000,
        maxAttempts = 3,
        windowMs = 15000
    }
}
```
